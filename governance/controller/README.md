### Bounded PR handoff failure
A genuinely failed PR-handoff attempt preserves its task fingerprint and second-verifier observation in an authenticated `HOLD` issue receipt, with a bounded `PR_HANDOFF_<class>` failure class. GitHub worker exit 50 remains a real failure; a subsequent run can count that failed attempt against the task retry budget. Failed engineering delivery is distinct from a successful PR, and the official DoneCheck™ v1.2 and Human Threshold™ remain HOLD.

The existing controller now checks the last four **completed** native schedule runs in the real GitHub API, using an event-filtered query. The four consecutive runs must have the same exact current source SHA, successful workflow conclusion and successful privileged `worker` job; each of the three observed gaps must be positive and at most 420 seconds. A currently running schedule job is excluded until it can provide completed evidence. Old-source, incomplete, skipped, failed or widely spaced runs remain HOLD. On a real K02 PASS, a bot-authored Issue #192 record carries the run IDs, gaps and hash. This is field evidence only; DoneCheck™ and Human Threshold™ retain their distinct final authority. GitHub `schedule` itself is best-effort; passing simulations never imply native delivery.
