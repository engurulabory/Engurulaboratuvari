## Finished Ability™ chain

`UNDERSTAND → DISCOVER → ARCHITECT → EXECUTE → TEST → USER_VERIFY → RECOVER → FINISH`

Every stage requires inspectable real-field evidence.

### Stage meanings

- **UNDERSTAND** — preserve the actual user objective, locked decisions and success boundary.
- **DISCOVER** — read current repository/runtime/evidence truth before changing it.
- **ARCHITECT** — choose the smallest coherent implementation path under `reuse → extend → adapter → new core`.
- **EXECUTE** — perform the bounded real change.
- **TEST** — run relevant tests, security/authority gates and regressions.
- **USER_VERIFY** — verify the produced result against the user-requested outcome and visible product/task acceptance surface. This stage does not replace a separate Human Threshold when one is required.
- **RECOVER** — exercise real failure diagnosis and bounded repair when the field task exposes a failure.
- **FINISH** — Mandatory DoneCheck™, canonical merge/state transition and post-finish verification.

A critical stage failure forces HOLD; aggregate success cannot hide it.

## Specialist Spawn Guard

A bounded specialist is eligible only when:

1. a verified capability gap exists, or
2. a materially useful independent second view is justified.

The specialist receives:
- bounded scope;
- bounded step budget;
- capabilities no broader than the parent task;
- exactly the same Human Threshold boundaries.

Rule:

`specialization ≠ privilege escalation`

## Governed Tool-Gap Proposal

Canonical flow:

`TOOL_GAP → PROPOSAL → AUTHORITY REVIEW → SECURITY REVIEW → COST REVIEW → BOUNDED TEST → EVIDENCE → ACCEPT / REJECT`

An ACCEPT decision records that a proposal is suitable for governed integration work. It does not itself authorize installation, credential creation, external connection, publication or irreversible action.

## Human Intervention Reconciliation Gate

After Human Threshold, takeover or any human action that changes real state:

`checkpoint → human intervention → re-read repo/runtime/artifact/task state → diff → reconcile → NEW_VERIFIED_STATE → resume`

The old checkpoint is historical evidence, not current authority.

Required reread surfaces:
- repository;
- runtime;
- artifact;
- task state.

Detected differences must be reconciled before execution continues.
